## 1. 产品概述

### 1.1 一句话定位

她测是一款面向产品经理、设计师和测试人员的**女性友好与安全情境审查工具**。它不评价界面是否漂亮、顺手或"像女性产品"，而是检查：当女性处于共享设备、亲密关系控制、位置暴露或持续骚扰等现实情境中时，产品设计是否仍能保护她的隐私、控制权与求助能力。系统通过网站和截图定位具体页面与交互，将证据不足处转为待办；用户补充并确认事实后，后台只更新对应风险，最终生成有依据的风险反馈与测试用例。

### 1.2 产品边界：明确不做什么

- 不评价配色、文案语气或一般可用性；
- 不做通用 UX 测试（"按钮不明显、流程不顺"类问题一律不输出）；
- 不让 AI 扮演笼统的"女性用户"；
- 不把材料缺失直接判定为产品缺陷；
- 不构成法律意见、安全认证或替代真实用户研究。

### 1.3 五大审查维度（首版固定，不得增删语义）

| 维度 | 核心问题 | 典型产品证据 |
|---|---|---|
| 隐私暴露 | 锁屏通知、搜索记录、真名和联系方式是否会在非自愿情况下暴露 | 通知预览、历史记录、账号发现设置 |
| 关系性控制 | 他人能否借助设备、账号或权限持续监视和控制用户 | 登录设备、改密后会话、权限撤销 |
| 位置与行程 | 产品是否默认或持续暴露位置、活动轨迹和规律 | 定位权限、分享对象、停止共享后的状态 |
| 骚扰阻断 | 拉黑、举报和可见范围能否阻止对方绕过限制继续接触 | 私信、评论、群聊、新账号和举报流程 |
| 求助与补救 | 用户遭遇风险后能否安全保存证据、快速退出、删除内容并获得反馈 | 证据保存、快速退出、申诉、删除与处理通知 |

图层识别只是把问题定位到具体按钮、卡片和状态的手段；真正的产品价值是把上述女性处境转化为研发能够确认、修改和复测的产品问题。

### 1.4 研究依据

规则库每条规则必须标注来源。基线来源：GenderMag、UN Women（技术促成的针对女性的暴力）、Safety Net Project 开发者指南、Refuge Tech Safety 开发者清单。

### 1.5 Demo 开场声明（强制）

> 她测不是通用 UI 可用性工具。截图和图层用于定位证据，产品最终审查的是女性在隐私、控制、位置、骚扰与求助情境中的安全。

### 1.6 产品不变量（开发争议的裁决依据）

1. **证据不足 ≠ 风险**：材料缺失只能生成待办或风险假设，永远不能直接判定产品缺陷。
2. **用户确认前不写入**：AI 只产出"拟写入证据摘要"，确认后以事务方式提交，失败回滚。
3. **增量更新不串线**：一次补充只更新关联 Finding；若可能影响其他风险，新建关联待办而非静默修改。
4. **确定性优先，AI 按需调用**：图层识别、校验、排版全部由普通程序完成；只有理解、推理、追问才调用模型。
5. **审查情境不审查审美**：严格限定五维度，不输出通用 UX 问题。

## 2. 用户与场景

### 2.1 目标用户

产品经理、设计师、测试/安全人员；黑客松评委与观众为演示场景受众。

### 2.2 核心用户故事

- 作为产品经理，我上传竞品/自家产品截图，希望得到"哪些设计在女性风险情境下有隐患"的可执行清单，而不是泛泛的可用性意见。
- 作为测试人员，我希望每条风险附带 Given-When-Then 用例，能直接进测试用例库复测。
- 作为设计师，我希望系统标出"证据不足"的地方，我补充截图后它只更新对应结论，不推翻其他结论。

### 2.3 演示动线（黑客松）

创建项目 → 上传网站 URL + 截图 → 系统解析生成证据包 → 用户确认产品理解与交互覆盖 → 查看截图图层（标注模式 → 风险图层模式）→ 点击待办进入对话 → 补充截图/回答 → AI 生成拟写入证据摘要 → 用户确认 → 后台只更新关联风险 → 查看风险报告与测试用例。

## 3. 功能需求

### F1 上传产品

**F1.1 材料类型与优先级**

| 层级 | 输入 | 作用 |
|---|---|---|
| 首选 | 网站 URL | 观察实际页面，安全探索可逆交互 |
| 首选 | PNG/JPG 截图 | 定位界面状态、弹窗、流程和视觉证据 |
| 补充/替代 | PDF | 网站或截图不足时补充原型、报告和设计说明 |
| 补充/替代 | DOCX、Markdown、TXT | 补充 PRD、后台规则、异常状态和恢复机制 |

**F1.2 输入限制（成本护栏）**

- 每项目最多：1 个网站、3–5 个网页、12 张截图、20 页 PDF；
- 单文件上限（工程建议值，可配置）：图片 ≤ 10MB、PDF ≤ 50MB、文档 ≤ 5MB。

**F1.3 材料不足引导**

首先提示用户提供网站和截图；若产品未实现、网站需登录、不便公开或截图不足，用户说明原因后可使用 PDF 或产品文档继续。**至少提供一种可解析材料即可开始**，四种材料不要求全部提供。

**F1.4 解析管线（全部为确定性程序，不调用 AI）**

- URL → 服务端 Playwright 安全截图与文本提取；
- 图片压缩、裁切、感知哈希（pHash）去重；
- PDF 拆页；DOCX/Markdown/TXT 读取；OCR（中文，作为兜底，允许人工补充）。

**F1.5 产品证据包**

系统将材料统一整理为"产品证据包"，包含：页面（pages）、控件（controls，即候选图层）、用户任务、页面关系、文档规则、交互覆盖情况、来源位置（sourceIndex）。

**F1.6 验收标准**

- [ ] 上传页按优先级引导，说明原因后可切换到补充材料；
- [ ] URL/截图/PDF/DOCX/MD/TXT 六种输入至少五种可解析进入证据包；
- [ ] 超出数量/大小限制时给出明确提示而非静默失败；
- [ ] 相同内容（pHash 命中）不重复计入证据包；
- [ ] 每条证据可回溯到来源（文件/页码/URL/坐标）。

### F2 截图图层审查台

**F2.1 确定性图层检测（前端完成，零模型费用）**

截图进入项目后，系统先把页面中的按钮、输入框、卡片、图标和面板拆成可点击的"视觉候选图层"。基础 Demo 通过像素边缘检测（Sobel）、色块与连通区域分析，真实计算矩形候选区域。该能力只回答"页面上可能有哪些视觉对象"，不理解业务含义或跨页面风险。

**F2.2 双模式**

- **标注模式**：用于确认系统是否找对对象（人工核对候选图层）；
- **风险图层模式**：用颜色、文字和图标共同表达四类状态——已确认风险、需补充证据、已有保护、未确认。

**F2.3 人工修正（必须支持）**

手工框选漏识别区域、修正边界、修改类型、删除误识别。

**F2.4 图层与规则关联**

每个候选图层可关联一条女性安全规则（来自规则库），例如"锁屏通知是否暴露求助内容""停止分享后位置是否真正失效""拉黑后能否绕过接触"。

**F2.5 五选项确认流**

用户点击图层后可选择：

1. 产品没有这个设计；
2. 已有设计，但截图未上传（→ 页面显示补充截图入口）；
3. 目前无法确认；
4. 其他情况；
5. 产品已有保护机制。

**F2.6 补充截图绑定**

选择"已有设计，但截图未上传"时，新材料绑定当前图层、待办和风险，**先进入待复核，不能自动判定风险消失**。

**F2.7 状态同步**

图层、待办、确认选项、补充截图四者状态必须一致联动。

**F2.8 验收标准**

- [ ] 无任何 AI 调用参与下，截图可产出候选图层；
- [ ] 标注模式与风险图层模式可切换，四类状态视觉可区分（颜色+文字+图标三重编码）；
- [ ] 人工新增、删除、边界修正、类型修改均可用；
- [ ] 五选项确认流完整，"截图未上传"正确唤起补充入口；
- [ ] 补充截图进入待复核而非自动消除风险；
- [ ] 在 3–5 张真实产品截图上，自动检测的召回率足以支撑演示（人工框选可补位）。

### F3 待办清单与独立对话

**F3.1 待办生成**

系统完成初始识别后，不直接把疑点判定成风险，而是生成 **3–5 个高价值待办**（每次初始分析最多 5 个）。四类典型来源：

- 识别到按钮，但缺少点击后的页面或状态；
- 产品有开启流程，却没有说明撤销、异常或恢复机制；
- 网站、截图和文档对同一功能的描述不一致；
- 界面无法证明后台权限、数据删除或多设备同步行为。

**F3.2 待办字段**

标题、优先级、提出原因、关联证据、关联风险、处理状态。

**F3.3 独立对话线程**

每个待办一个独立 AI 对话线程；**不同待办的对话与证据不能互相串线**。打开待办不调用模型（首个问题、提出原因和引用证据已由初始分析生成，页面直接加载）。

**F3.4 轮次限制**

每个待办最多 **3 轮 AI 追问**，超过后转为人工确认。

**F3.5 模型每轮返回二选一**

- **信息不足**：提出一条最能改变判断的问题；
- **信息足够**：返回拟写入证据摘要和风险更新预览。

用户确认时不重复调用模型；后台以事务方式提交。新增材料、高风险复核或上下文实质变化时，可追加一次针对性验证调用。

**F3.6 验收标准**

- [ ] 初始分析后生成 3–5 个待办，字段完整、证据可跳转；
- [ ] 打开待办零模型调用；
- [ ] 对话上下文按待办隔离，切换待办不残留对话；
- [ ] 第 4 轮追问被系统拦截并转人工确认入口。

### F4 风险反馈与报告

**F4.1 拟写入证据摘要**

AI 先生成"拟写入证据摘要"，明确：准备记录什么事实、信息来自哪里、适用于什么范围、会影响哪个风险。**只有用户确认后，后台才写入证据并更新关联风险。**

**F4.2 事务写入**

证据写入必须绑定项目、待办和风险 ID，并保存更新前后状态。失败时回滚，**不允许半完成结果进入报告**。

**F4.3 关联影响**

若新信息可能影响另一个风险，系统创建新的关联待办，**不静默修改其他结论**。

**F4.4 四类结论**

| 类型 | 含义 |
|---|---|
| 已确认风险 | 现有证据已经能够证明问题存在 |
| 待验证风险 | 有合理风险，但仍需后端、真实环境或人工验证 |
| 需求缺口 | PRD 尚未定义关键状态或规则 |
| 已有保护 | 用户补充的信息证明产品已有保护机制 |

**F4.5 结论字段**

每条结论包含：材料来源、观察事实、用户确认事实、模型推断、严重程度（建议分级：高/中/低，v0 采用）、修改建议、Given-When-Then 测试用例。

**F4.6 报告与导出**

单页报告展示四类结论与全部字段；支持 Markdown/PDF 导出。

**F4.7 模型不可用时的处理**

现场网络失败、模型密钥缺失或供应商不可用时，保留上传与静态解析产物并明确提示稍后重试；不得生成或展示模拟结论。

**F4.8 验收标准**

- [ ] 确认前不写入；确认后 Evidence Update 可追溯前后状态；
- [ ] 单项补充只更新关联 Finding，其他 Finding 状态不变；
- [ ] 每条结论具备来源、四类事实区分（观察/确认/推断）与 GWT 用例；
- [ ] 报告可导出 Markdown 与 PDF；
- [ ] 模型不可用时不生成替代结论，并保留可继续分析的静态解析产物。

## 4. 数据模型（核心对象）

| 对象 | 职责 | 关键字段（v0） |
|---|---|---|
| AuditProject | 审查项目 | id、名称、状态、预算配置、创建/更新时间 |
| InputArtifact | 输入材料 | id、projectId、类型(url/image/pdf/docx/md/txt)、来源地址、pHash、解析产物引用、状态 |
| EvidencePackage | 产品证据包 | id、projectId、pages、controls、userTasks、pageRelations、docRules、interactionCoverage、sourceIndex |
| InteractionCoverage | 交互覆盖 | 已覆盖交互、未覆盖交互、与图层的映射 |
| ReviewTodo | 待办 | id、projectId、标题、优先级、提出原因、关联证据、关联 findingId、状态 |
| TodoConversation | 待办独立对话 | id、todoId、消息列表（角色/内容/轮次）、上下文摘要 |
| EvidenceUpdate | 用户确认后的结构化证据 | id、projectId、todoId、findingId、更新前状态、更新后状态、确认人、事务状态 |
| Finding | 风险发现 | id、projectId、类型（四类）、严重程度、材料来源、观察事实、用户确认事实、模型推断、修改建议、状态 |
| TestCase | 测试用例 | id、findingId、Given/When/Then |
| ModelInvocation | 模型调用记录 | id、函数名、模型、Prompt 版本、规则版本、Schema 版本、输入 Hash、Token、时延、费用、是否缓存命中、结果是否被采用 |

**待办状态机：**

```
待处理 -> 对话中 -> 待确认写入 -> 已完成
                        |
                        v
                   重新评估中 -> 待确认写入
待处理/对话中 -> 需人工确认
任意调用态  -> 可重试错误
```

**Finding 状态：** 初始假设 → 待验证 → 已确认风险 / 需求缺口 / 已有保护（终态可被新证据重新打开，重新打开必须走新待办）。

## 5. AI 调用规范

### 5.1 调用边界

**不调用 AI（普通程序完成）：** URL/文件格式校验；网页文本提取与截图；PDF 拆页、DOCX/MD/TXT 读取与 OCR；图片压缩/裁切/去重；截图像素读取、边缘检测、矩形候选区域与图层叠加；图层点击、手工框选、状态颜色与待办同步；补充截图绑定；材料来源索引；报告编号、排序、排版；打开待办、查看报告与普通保存。

**调用 AI（仅以下情形）：** 给图层命名/理解交互目的、提出风险问题、阅读补充证据、判断跨页面逻辑时，且只通过网关三函数进入。

### 5.2 网关三函数（业务代码不得绕过网关直连供应商）

```
analyzeProject(evidencePackage, rules, schema)      // 项目级初始分析，每项目原则上一次
continueTodo(todoContext, userInput, rules, schema) // 待办级增量调用，用户输入触发
verifyHighRisk(finding, evidence, rules, schema)    // 高风险 Finding 独立一致性复核
```

### 5.3 初始分析输出 Schema（v0）

```json
{
  "product_summary": {},
  "pages": [],
  "flows": [],
  "interactions": [],
  "evidence_gaps": [],
  "material_conflicts": [],
  "todos": [],
  "initial_findings": []
}
```

证据不足时只能创建待办或初始风险假设，**不能输出确定风险**。

### 5.4 待办级调用输入

每次只发送：当前 todoId、findingId、关联证据、必要的对话摘要、本轮输入、相关规则、当前风险状态。

### 5.5 模型配置（阶跃星辰 StepFun 系列）

- 接入方式：阶跃星辰 StepFun OpenAI 兼容接口；带截图调用 `step-3.7-flash`，纯文本调用 `step-3.5-flash-2603`，均可通过环境变量覆盖；
- 温度 0.1（允许范围 0.0–0.2）；
- 严格 JSON Schema + zod 双层校验；
- 高风险结果追加独立一致性检查（verifyHighRisk）。

### 5.6 网关横切能力

模型选择、图片与文本消息组装、超时控制、有限重试（格式错误/限流/临时网络错误可重试；权限、密钥、预算、不支持格式**不自动重试**）、限流、缓存（相同材料+模型+Prompt+规则+Schema 版本按输入 Hash 命中）、预算检查（用户/项目/每日三档，调用前检查）、脱敏日志、Token/时延/费用统计、供应商错误归一化。

### 5.7 版本记录

每次调用保存模型、Prompt、规则和 Schema 版本及输入 Hash（存 ModelInvocation），保证结论可复现、可回归。

## 6. 规则库规范

### 6.1 规则格式

| 字段 | 说明 |
|---|---|
| rule_id | 编号（如 PRI-001 / CTRL-001 / LOC-001 / HRAS-001 / HELP-001） |
| dimension | 所属维度（五维度之一） |
| statement | 核心问题陈述（一句话） |
| evidence_required | 判定所需的最小证据（哪些页面/状态/文档规则） |
| source | 研究依据（GenderMag/UN Women/Safety Net/Refuge 等） |
| version | 规则版本 |
| examples | 正例与反例各一（重点约束"没有看到 ≠ 没有设计"） |

### 6.2 v0 规模

20–30 条，五维度每维度 4–6 条。v0 冻结后进入代码库随版本发布。

### 6.3 演进原则

MVP 不微调模型；只有积累足够多、经专业复核的案例并稳定判定标准后，再评估微调。

## 7. 非功能需求

### 7.1 成本限制

- 每项目最多 1 个网站、3–5 个网页、12 张截图、20 页 PDF；
- 每次初始分析最多 5 个待办；每个待办最多 3 轮追问；
- 只发送当前任务需要的页面、规则和对话摘要；
- 相同材料、模型、Prompt、规则和 Schema 版本使用缓存；
- 调用前检查用户、项目和每日预算；
- 记录 Token、时延、费用、缓存命中和用户是否采用结果。

### 7.2 安全要求

- API Key 只保存在后端环境变量或密钥服务，不进入前端、代码仓库或日志；
- 上传前说明模型处理方、用途、保存期限和删除方式（知情同意页）；
- 默认不允许供应商使用材料训练模型（接入配置核对）；
- 网站分析不执行支付、发布、举报、删除、改号和位置共享等高影响动作（安全探索白名单：仅可逆交互）；
- 删除项目时联动删除原文件、OCR、缓存、证据包和报告。

### 7.3 失败降级矩阵

| 故障 | 降级行为 |
|---|---|
| OCR 失败 | 允许用户手工补充 |
| 个别页面失败 | 输出部分结果并标明缺失 |
| 模型不可用 | 保留预处理产物，允许稍后继续 |
| 格式错误/限流/临时网络错误 | 有限重试 |
| 权限、密钥、预算、不支持格式 | 不自动重试，明确报错 |
| 现场网络失败 | 保留预处理产物并明确报错，恢复后继续真实模型分析 |

## 8. 验收标准

### 8.1 成功标准（8 条，最终验收逐条勾选）

- [ ] 系统没有把材料缺失直接判断成产品缺陷；
- [ ] 待办确实能改变风险分类或补全需求；
- [ ] 用户确认前不写入正式证据；
- [ ] 单项补充只更新关联风险；
- [ ] 每条风险具备材料来源、依据和可执行测试用例；
- [ ] 同材料、同模型、同规则版本的主要结论基本一致；
- [ ] API Key、预算、删除和失败降级路径可用；
- [ ] 团队能够清楚说明 AI 在哪里调用、为什么调用以及一次调用发送了什么。

### 8.2 MVP must-have 清单（黑客松 Demo 验收）

- [ ] 一次无需 AI 的截图候选图层识别；
- [ ] 至少展示三类明确的女性友好风险规则（不得用通用 UX 问题代替）；
- [ ] 标注模式与风险图层模式；
- [ ] 自动图层的人工新增、删除和边界修正；
- [ ] 图层、待办、确认选项和补充截图的状态同步；
- [ ] 一次项目级多模态分析；
- [ ] 产品理解确认和交互覆盖图；
- [ ] 3–5 个高价值待办；
- [ ] 单待办对话；
- [ ] Evidence Update 确认写入；
- [ ] 单风险增量更新；
- [ ] 3–5 个高质量 Finding；
- [ ] Given-When-Then 测试用例；
- [ ] 单页报告和模型不可用时的明确错误处理。

范围说明：自动深度爬取网站延后，首版支持公开 URL 的单页或少量指定页面读取和安全探索。

## 9. 评测集规范

### 9.1 案例结构

| 字段 | 说明 |
|---|---|
| case_id | 编号 |
| 输入材料 | 网站/截图/文档组合（固定样本） |
| 期望待办 | 期望生成的待办标题与数量 |
| 期望 Finding | 期望的结论类型与严重程度 |
| 期望误报拒绝 | 明确不应判为风险的点（材料不足/已有保护） |
| 依据规则 | 命中的 rule_id |

### 9.2 v0 规模与覆盖

15–20 组，覆盖三类：正确风险识别、误报拒绝、期望待办生成。

### 9.3 回归方式

评测作为 AI 回归基线：锁定材料、模型、Prompt、规则与 Schema 版本，跑分对比；同版本结论一致性是成功标准第 6 条的度量来源。
