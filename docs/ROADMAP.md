## 1. 技术栈清单

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Next.js 15（App Router）+ React 19 + TypeScript 5（strict） | 前后端一体；三页面 + API Routes |
| UI | Tailwind CSS + shadcn/ui | 快速搭建一致界面 |
| 状态管理 | Zustand | 审查台需要图层↔待办↔证据跨组件同步 |
| 图层引擎 | 自研 TS：OffscreenCanvas + Sobel 边缘检测 + 连通区域标记 + 矩形合并 | 零模型费用、可单测；备选：opencv.js（自研不达标时切换） |
| ORM/数据库 | Prisma + SQLite（MVP）→ PostgreSQL（正式版） | MVP 零配置；schema 平移 |
| 网页取证 | Playwright（Chromium，服务端） | 公开 URL 截图 + 安全探索（仅可逆交互白名单） |
| 图片处理 | sharp + pHash | 压缩、裁切、感知哈希去重 |
| 文档解析 | pdfjs-dist（PDF 拆页）、mammoth（DOCX）、原生 MD/TXT | 覆盖全部补充材料 |
| OCR | Tesseract.js + 中文语言包 | 兜底，允许人工补充 |
| AI 网关 | 阶跃星辰 StepFun OpenAI 兼容接口 + zod 双层校验 | 业务代码禁止直连供应商接口 |
| 测试 | Vitest（单测/快照）+ Playwright Test（E2E）+ 评测集回归 | 图层算法用固定截图快照断言 |
| 工程化 | pnpm + ESLint + Prettier + GitHub Actions（lint/test/build） | Node 20+ |
| 部署 | MVP：本地运行（Demo 最稳）；正式版：Docker / Vercel 可选 | 模型不可用时保留静态解析产物并明确报错 |

## 2. 系统架构

```
apps/web (Next.js 单仓库)
├── app/                          # 页面与 API
│   ├── /(pages) upload / review / report
│   └── api/
│       ├── projects              # 项目 CRUD
│       ├── artifacts             # 材料上传与解析
│       ├── analysis              # 触发项目级初始分析
│       ├── todos / todos/[id]/messages   # 待办与独立对话
│       ├── evidence-updates      # 拟写入摘要 → 确认 → 事务写入
│       ├── findings              # 风险查询与报告
│       └── reports/export        # Markdown/PDF 导出
├── lib/
│   ├── ai-gateway/               # 唯一模型出口（三函数 + 横切能力）
│   │   ├── analyzeProject.ts / continueTodo.ts / verifyHighRisk.ts
│   │   ├── cache.ts / budget.ts / retry.ts / invocation-log.ts
│   ├── parsers/                  # url / pdf / docx / md / ocr / dedup
│   ├── layers/                   # 图层检测算法（纯函数，可单测）
│   ├── rules/                    # 规则库加载与版本
│   └── state/                    # 待办状态机（集中管理）
└── prisma/schema.prisma          # 10 个核心对象
```

关键约束：`lib/ai-gateway` 是模型调用唯一出口；待办状态流转集中在 `lib/state`；图层算法为纯函数、与 UI 分离。

## 6. 开发流程

### 6.1 Git 工作流

- `main` 受保护；`feature/*` 短生命周期分支；PR 至少 1 人评审后合并；
- 约定式提交（feat/fix/docs/test/chore）；
- CI（GitHub Actions）：lint + typecheck + test + build 全绿才可合并。

### 6.2 代码规范

- TypeScript strict；ESLint + Prettier 统一格式；
- 注释使用中文，解释意图与约束（尤其状态机与网关横切逻辑）；
- 组件/函数命名与 PRD 对象名对齐（ReviewTodo、Finding 等不得另造同义词）。

### 6.3 测试策略

| 层 | 方式 |
|---|---|
| 图层算法 | 固定截图集 + 快照断言（期望矩形集合，带容差） |
| 状态机 | 全路径单测，含回滚与失败注入 |
| AI 网关 | 供应商 SDK 全 mock；重试/超时/预算/缓存分支全覆盖 |
| E2E | Playwright 三页面主流程（上传→审查→待办→报告） |
| AI 回归 | 评测集 + 版本锁定（材料/模型/Prompt/规则/Schema） |

### 6.4 AI 编码协作规范

小步提交；每个任务先明确 DoD 再动手；AI 生成代码必须过 lint + test + 人工评审；涉及状态机与事务写入的改动必须补测试。

### 6.5 同步机制

每日 15 分钟站会对齐三线进度；每个里程碑出口做正式评审（对照 DoD），不达标不进入下一里程碑。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 图层检测准确率不足 | Demo 观感、人工修正成本 | M2 T2.0 第一天实测；不达标切 opencv.js 或简化"色块+网格"方案（人工框选兜底） |
| StepFun JSON 输出不稳定 | 解析失败率高 | zod 双层校验 + 有限重试 + 修复重提示；M0 实测锁定型号 |
| 状态机/事务 bug | 数据不一致、半完成结果 | 状态流转集中一个模块；全路径单测 + 失败注入 + 回滚测试 |
| 成本超支 | 预算失控 | 三档预算检查 + 输入哈希缓存 + 费用看板每日巡检 |
| OCR 中文质量差 | 证据缺失 | 人工补充兜底（需求已定义）；Demo 选清晰材料 |
| 现场网络/模型故障 | Demo 失败 | 保留静态解析产物、明确报错并提供重试入口 |
| 并行三线集成冲突 | W3 集成期返工 | 接口契约（API + zod Schema）在 M0/M1 提前冻结 |

## 8. Demo 演示脚本（W4 彩排基准）

1. **开场声明**（强制）：她测不是通用 UI 可用性工具，审查的是女性在隐私、控制、位置、骚扰与求助情境中的安全；
2. 上传准备好的示例产品（URL + 3–5 张截图），展示材料优先级引导；
3. 展示证据包与交互覆盖图 → 现场确认产品理解；
4. 图层审查台：标注模式核对候选图层 → 人工框选修正一个漏识别 → 切风险图层模式看四类状态；
5. 点开一个待办 → 补充截图/回答提问 → AI 生成拟写入证据摘要 → 确认 → **展示只更新了关联风险，其他结论未动**；
6. 报告页：四类结论、来源追溯、GWT 测试用例、导出 PDF；
7. 收尾：说明 AI 调用点（三函数）、成本护栏与失败恢复路径；
8. 异常预案：断网或模型不可用时展示明确错误，不产生模拟分析结果。
